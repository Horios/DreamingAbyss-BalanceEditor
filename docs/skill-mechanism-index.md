## 操作

在「技能與戰鬥 → 技能、裝備與寶石」選取技能，即可看到「使用中的機制」。卡片顯示穩定 ID、來源、參數、使用技能數、支援／重用狀態，以及狀態或技能相依。

1. 列表及詳細頁的「複製技能」產生新 ID 與追加的引擎索引；多職業技能為每個職業分配獨立索引。完整複製保留處理器、來源限制及相關設定，但不會自動加入職業解鎖表、夥伴配置或怪物技能清單。副本仍需按設計配置取得入口。
2. 「建立空白技能」建立合法、停用、零效果量的技能，可選職業與主動／觸發／輔助／被動類型。引擎沒有真正的無效果類型，因此空白技能使用零倍率／零數值的最小設定。
3. 「複製機制」「從其他技能加入機制」「從既有技能取用機制」開啟同一個選擇視窗。可搜尋來源技能，多選機制，指定目前／其他／新技能。只複製選取項目。
4. 先「預覽與檢查」：列出實際新增／替換欄位、數值、狀態副本與跨技能引用。替換既有欄位須勾選允許替換。更改設定後必須重新預覽。確認時重新驗證整份候選資料，失敗不寫入。
5. 狀態相依預設複製一份新狀態 ID，避免調整副本時影響來源。也可明確選擇既有狀態，介面會指出這是共用定義。誘發指定技能必須明確重新指定或保留原引用，並檢查角色、職業、自我引用及誘發再誘發限制。
6. 「編輯參數」調整獨立實例 JSON；完整技能 JSON 仍可編輯既有欄位與專屬設定。選用效果可移除；主效果不可留空，需明確替換。被動至少保留一個效果。
7. 點機制進入積木箱詳情，查看所有使用技能及取用範例；點技能回到編輯頁。「返回上一頁」保留技能與機制搜尋條件。狀態連結精準開啟狀態製作器，相關怪物連結開啟所在世界地圖並篩選該怪物，均提供返回技能機制。
8. 技能文字草稿獨立保存在瀏覽器。跳轉先提醒，保留草稿供返回後繼續編輯；匯出與發布前需先套用或捨棄。關閉頁面也有未套用提醒。

## 支援分類

| 分類 | 穩定 ID | 操作與限制 |
| --- | --- | --- |
| 核心主效果 | `core.damage/drain/heal/shield/cleanse/dispel/revive/applyStatus` | 複製、編輯；只有一個主效果槽，替換須確認 |
| 核心選項 | `core.target/hitCount/powerBasis/damageResolution/onHitStatus` | 複製、編輯、移除；需相容的一般核心主效果 |
| 誘發 | `core.induction` | 複製、編輯；最多 2 個目標，一次誘發，指定技能相依必須明確選擇 |
| 職業特殊效果 | `system.taunt/guard/slow/regen` | 複製、編輯；沿用人物核心技能覆蓋主效果的行為，不標示為怪物通用效果 |
| 輔助持續效果 | `support.<kind>` | 依現有 guard、attack、critical、power、regen、fracture、weaken、damageAmp、followup、dotAttack、dotMaxHp、applyStatus 等處理器；只能取用至輔助技能 |
| 被動效果 | `passive.<key>` | 現有被動模型支援的能力；逐項複製、編輯、移除，目標方向必須相容 |
| 關聯狀態內部 | `status.periodic.damage/heal`、`status.modifier.<kind>`、`status.control.<kind>`、`status.stackable/uses/instant` | 查看、反查、跳轉來源；透過施加狀態機制一併取用，不直接貼入技能根層 |
| 普攻觸發 | `event.proc` | 查看及來源引用；完整技能複製保留觸發參數。它不是受擊觸發 |
| 專屬處理器 | `exclusive.polymorph/freeze/frost/rage/summonMorphTrap/summonFreezeTrap/fear/tauntRage/nextActiveDamage/advanceNextRound/shieldLowest` | 僅查看／來源引用；不能單獨重用。完整技能複製保留原處理器並顯示限制 |
| 未知處理器 | `exclusive.<原始 effect>` | 明確標示尚未結構化，保留原始資料，不假設可用 |

積木箱以目前資料實際使用的機制建立索引，使用技能數與實例數分開計算。同一技能多次使用同機制只計為一個技能。先依目前技能的引擎相容性排序，再優先常用可重用及本次工作階段近期取用的機制；低使用率項目不刪除。空索引不以虛構技能填充。

## 格式與相容性

機制定義及範例索引僅存在編輯器程式中，機制實例仍是原有技能欄位與狀態 ID 引用。沒有新增遊戲 schema、沒有批次遷移舊技能、沒有把中文名稱用於機制判定，也沒有把索引／草稿中繼資料放入遊戲 JSON。

`systemEffect` 會短路一般主效果，因此例如繩索陷阱只顯示實際緩速處理器，不錯列為傷害加緩速。舊版沒有 canonical 系統的資料仍沿用既有 `fromLegacy`／`normalizeDocument` 適配，不增加第二套遷移器。回退只需還原本次平衡器 commit 或前一個 Sites 版本；無遊戲資料遷移需要撤銷。

## 限制

- 無任意多主效果堆疊、門檻比較、死亡事件或跨單位憤怒方案編輯器。這些不會被標示為已實作；題述 BOSS 僅作設計案例，沒有新增戰鬥邏輯。
- 專屬控制、陷阱與低階硬編碼處理器尚未通用化。機制選擇視窗保留並說明限制，禁止單獨貼用。
- 相關狀態的週期／修飾／控制項目須在狀態製作器調整。選擇「既有狀態」時是明確共用該狀態定義；預設複製才是完全獨立的狀態參數。
- 新技能及副本不會自動加入任何角色、怪物或掉落入口，以免悄悄改變既有平衡。
- 搜尋與機制索引可處理 1024 筆定義；仍遵守既有單職業核心／輔助 64 個及被動 512 個的引擎上限。
