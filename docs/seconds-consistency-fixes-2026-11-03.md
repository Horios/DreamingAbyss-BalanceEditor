# 秒數資料一致性修正報告

## 範圍

平衡器基準：`v2-developer-mode`，25af872。遊戲修正從 `chatgpt-dev` a3434bf / v0.036 建立獨立分支 `fix/seconds-data-consistency-20261103`，不寫入 Claude 正在維護的 `chatgpt-dev`。兩者分開提交；遊戲分支的整合及測試站部署由後續合併決定。

## 修正對照

| 問題 | 修正結果 |
|---|---|
| 永久旗標與正式持續秒數不同步 | 狀態頁、秒數頁及機制編輯共用同步規則。永久對應 `durationSeconds: null`；取消永久回復有限秒數；可直接輸入小數秒。匯出與發布服務拒絕互相矛盾的文件，無效輸入保留原資料。 |
| 修改舊技能時間卻不影響實際戰鬥 | `cooldown`、`duration`、`bossDuration` 在技能編輯時作唯讀相容欄位；修改會明確拒絕並指出對應 `timing` 欄位，不能假裝套用成功。 |
| 被動事件與裝備的回合點數不透明 | 新增「被動事件秒數」及「裝備冷卻秒數」編輯分類。以秒數呈現及輸入，依既有職業間隔／事件基準反算相容點數；非整數點數步進拒絕。裝備、共用模板、品質詞綴與實際詞綴池保留原有價值；同一來源的職業視圖共用原資料。指定 proc 的點數仍表示觸發率，不誤標為秒數。 |
| 戰報將 1 回合直接換成 1 秒 | 遊戲獨立分支以實際縮減量產生戰報。既有魔力循環仍減少 3 秒、內部冷卻 6 秒，數值不變。週期引爆改為明確名稱。 |
| 部分描述仍有回合文字 | 遊戲獨立分支更新魔力循環、冰凍陷阱、神聖光牢原始描述。平衡器狀態清單顯示正式秒數，並明確標示舊時計及舊時間為相容資料。 |
| 欄位顯示與實際能力不一致 | 空值代表永久只適用於狀態；技能空白不再當永久輸入。信物首次觸發與週期間隔只在週期事件顯示，持續秒數只在持續增益動作顯示；歷史文件未升級前不開放秒數控制。 |
| 回合事件名稱與秒數執行不一致 | 保留穩定識別碼 `targetTurnEnd`，介面改為「固定週期觸發（受控仍觸發）」，明示其使用 `triggerIntervalSeconds`，與實際完成行動的 `targetActionEnd` 分開。沒有變更觸發頻率。 |

## 資料及相容性

- 沒有自動重設技能倍率、冷卻、掉落率或裝備數值。
- 原始相容欄位保留，既有新舊文件與存檔沿用原有格式；本次不建立第二份資料模型。
- 秒數輸入保留舊引擎整數點數的限制，並明確說明換算步進。共用裝備與詞綴由同一份來源編輯，不把職業視圖誤當成獨立資料。
- 遊戲獨立分支版號遞增至 v0.037，並更新被修改 JavaScript 的快取版本。若 Claude 的工作分支已推進版號，合併時依最新版本再次檢查。
- 平衡器封裝的遊戲預覽與發布 validator 仍以現行 `chatgpt-dev` 為基準；獨立分支的戰報及遊戲原始描述修正，在合併前不宣稱已部署到遊戲測試站。

## 驗證

新增測試驗證永久／有限小數秒往返、非法修改回復、舊欄位明確拒絕、事件秒數反算、裝備點數反算及不適用信物欄位隱藏。瀏覽器測試另外確認實際勾選永久、輸入小數秒、匯出及套用至真正遊戲的結果。

遊戲新增回歸案例比對時間軸實際冷卻減少量與戰報：12 秒降至 9 秒，文字必須是減少 3 秒。GitHub 推送、CI 結果及 Sites 部署在交付訊息分別回報；執行中或取消不計為通過。
